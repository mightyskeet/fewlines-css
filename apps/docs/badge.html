Badge

Compact status label: statuses and counters next to headings, tabs and list items. Static inline element — no states, no JS.

Semantic basis

The platform has no native badge element, so the component is a static <span> and adds no JS: no role, no focus, no hover. The label text is the value itself; for ambiguous counters the host supplies an accessible name via aria-label.

Canonical markup

<span class="ui-badge">Beta</span>

Adjacent badges get a gap automatically (.ui-badge + .ui-badge). The label never wraps (white-space: nowrap) — badges are short labels by contract.

data-variant="accent|success|warning|danger"; default is neutral (no attribute). Variant names mirror the semantic token families they consume. Surfaces come from the tint tokens (--ui-color-*-tint), labels from the -strong variant colors — the same feedback model as Alert, all pairs validated by the APCA matrix at the strict body threshold (Lc 75) in both themes.

Counters

Inbox 3

A bare number is rarely self-explanatory for assistive tech — the host adds aria-label when the count alone is ambiguous.

Accessibility

  • Badge is a generic inline element: no interactive role, not focusable, no states.
  • Color is never the only carrier of meaning (WCAG 1.4.1) — the label text states the status; variant styling reinforces it.
  • The 0.75rem label size relies on pairs validated at the strict body-role APCA threshold, not on the smaller-text allowances.

Do not

  • No interactive badges — a <button> or <a> styled as ui-badge is out of contract; actions belong to Button.
  • No variant classes — variants are expressed only via data-variant.
  • No multi-line pills — white-space: nowrap is part of the contract; multi-line labels belong in Alert or plain text.
