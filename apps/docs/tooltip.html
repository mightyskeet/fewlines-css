Tooltip

Short hint for an interface element: shown on hover or focus, dismissed with Escape or an outside click. Fully declarative — no runtime JS.

Semantic basis

The tooltip is a Popover API element (popover="hint") plus interest invokers (interestfor): in Chromium the browser shows it on hover/focus and hides it when interest is lost. Both features are progressive enhancements. In engines without interest (Firefox, Safari) a CSS-only fallback shows the same element on hover (pointer devices only) and keyboard focus — the click still stays the trigger's action (a "Save" button must save, not show a hint), and the description stays associated via aria-describedby for assistive tech. The fallback hint is shown by CSS, not through the popover API: Escape does not close it (it dismisses on pointer leave or blur), and it is not in the top layer.

Canonical markup

<button class="ui-tooltip-trigger"
        interestfor="tip-save"
        aria-describedby="tip-save">
  Save
</button>
<span class="ui-tooltip" id="tip-save" popover="hint">Saves your changes</span>

The trigger keeps its own styling (ui-button and friends); ui-tooltip-trigger only declares the anchor name. The hint is a sibling element, never a child of the trigger — child text would become part of the trigger's accessible name.

Example

Hover or focus the button: Saves your changes

The hint renders below the trigger, centered, and flips above automatically when there is no room (position-area + position-try-fallbacks, inside @supports). Several pairs on one page must be scoped: triggers share the --ui-tooltip-anchor name, and without scoping every hint anchors to the last trigger in DOM order — a Save hover would show a hint under another button. Wrap each pair in its own element with anchor-scope: all (or give each pair a unique anchor name).

For inert triggers (a "?" button with no action of its own) the host may opt in to click activation by adding popovertarget + popovertargetaction="show" — the hint then also opens on click in engines without interest. Never add it to action triggers.

Accessibility

  • aria-describedby is part of the canonical markup: it is the only description association in engines without interest invokers; where interest is supported the browser wires it natively.
  • WCAG 1.4.13 is native in the popover path: Escape dismisses, the pointer can move onto the hint text, the hint stays visible until interest is lost or it is dismissed. The CSS fallback keeps the hint hoverable and persistent, but Escape does not dismiss it (pointer leave/blur does) — a documented trade-off.
  • Keyboard: focus opens the hint in every engine (native interest, or the :focus-visible fallback), focus is never trapped. Escape closes the popover path; the CSS fallback hint dismisses on pointer leave or blur.
  • The tooltip role is implicit from popover="hint" — do not set it manually. Text uses the text/surface-raised pair, validated at the strict body APCA threshold (Lc 75) in both themes.

Do not

  • No JS for open/close — interestfor is declarative.
  • No popovertarget on action triggers — the click must perform the action, not show the hint; click activation is an opt-in for inert triggers only.
  • No interactive or long content inside the hint — that is a Popover; no custom placement attributes — the tooltip has one canonical placement with a native flip.
  • Do not use the title attribute — it is unstyleable and keyboard-inaccessible.
