Base lists

The semantic list elements get one canonical presentation from the base layer: the indent rides the spacing scale, nested ordered lists read as hierarchical numbering, the description list has a vertical canon and a receipt variant. No classes, no states of our own — the only switch is a data-attribute.

Semantic basis

These are native elements (ul, ol, li, dl, dt, dd) styled by bare element selectors in the base cascade layer — below components, so component classes always win. The UA fixed 40px start indent is normalized onto --ui-space-lg; markers stay native for ul and the top level of ol, so semantics and the start/reversed/ value attributes are untouched.

The top level keeps its native markers; nested levels read as hierarchical paths — 2.1, 2.1.1 — via counters(). Every ol resets its own counter and every li increments it, so the top level increments silently and the nested path composes for free. The hanging number is an absolutely positioned box anchored before the content: wider paths (10.10.10.) grow into the parent gutter instead of pushing or overlapping the text.

The numbering system is the host-overridable token --ui-list-counter-style — a counter-style name (decimal is the canon; georgian, lower-alpha or a custom @counter-style work too). It must stay a valid counter style: a garbage value invalidates the marker content and the number disappears.

A data-variant switch on the bare dl; every pair is grouped into a <div> (valid HTML — dl allows div-wrapped dt/dd groups), and the group is a wrapping row-reverse flex on shared baselines: rhythm between groups and inside a group is set independently. Values are placed before the key (order), so lone values sit on their own lines at the value edge, and the key lands on the last value's line — the receipt-total row — where it grows and leads to the value with a dashed dt::after. Canonical pairing is one dt per div; the DOM order (and the reading order) stays key-first.

Accessibility

  • list-style: none on the nested ol trips the WebKit quirk that strips list semantics for assistive tech — put the role="list" insurance on nested lists that carry meaning (the same contract the Timeline/Stepper/Tree components follow).
  • The counter path is exposed as generated content — the numbering reaches assistive tech with the item text.
  • The receipt leader is decorative: a border-strong line, repainted by forced colors.

Do not

  • Do not put component classes on list content — the base layer is the canonical presentation; a host re-themes via tokens, not wrappers.
  • Do not rely on start/reversed on nested ol — counters ignore them; those attributes work on the top level only.
  • Do not reference --ui-base-* tokens directly when restyling lists — use the semantic --ui-* tokens.
  • Do not style list markers via ::marker content — Safari does not support it; nested ol numbering is the ::before contract.
