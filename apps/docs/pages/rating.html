Rating

Whole-star rating input on a native radio group in a <fieldset>: the selection, the keyboard and the form participation come with the elements. No JS, no direction: rtl trick.

Semantic basis

Five <input type="radio"> in a <fieldset>: one selection, arrow-key stepping, Space, the group name from the legend and native fieldset[disabled] disabling — nothing to build. Whole steps only: half steps would mean 10 radios (double keyboard stops, half-value names) and stay outside the contract.

Canonical markup

<fieldset class="ui-rating">
  <legend class="ui-rating-legend">Your rating</legend>
  <label class="ui-rating-star">
    <input type="radio" name="rating" value="1" aria-label="1 star" />
  </label>
  <!-- … up to value="5" / "5 stars" … -->
</fieldset>

The label wraps its input (the implicit-label model of Choice): a click anywhere on the star toggles. The stars are empty elements — the shape is paint — so each control's name comes from the input's aria-label. The inputs are invisible but NOT removed from layout: they sit over the star box at opacity: 0, so the shared base :focus-visible ring outlines the star natively (no display: none — it would kill the keyboard).

The fill

The paint is two SVG-mask data-URI layers on the label (the Choice precedent — the shape belongs to the SVG, the color to the token): ::before the outline star (the empty state), ::after the solid star (brand) fading in. The filled look — the checked star plus every star before it — is forward-looking :has(), the DOM order is the visual order (no direction: rtl; LTR/RTL both come free from the logical properties). The hover preview (pointer-gated) only ever adds fill: hovering below the current selection changes nothing.

Disabled group

fieldset[disabled] — native group disabling; a single disabled radio dims the same way (:has(input:disabled)).

Customization

One density; the star box scales via the local token (default 1.5rem = 24px — the WCAG 2.5.8 minimum target size): 

.rating-compact {
  --ui-rating-size: 1.25rem;
}

The fill follows the brand family by default; hosts re-theme through semantic tokens in place — no variants, no classes.

Accessibility

  • Native radio semantics: arrows step through the stars, Space selects; each value is announced with its aria-label, the group with the legend.
  • The state is not carried by color alone (WCAG 1.4.1): the shape changes from outline to solid.
  • Filled star: brand/surface-tint — the registered Progress fill pair (nonText); the empty outline is surface-tint on the surface (the Slider rail model).
  • Forced colors: the outline takes CanvasText, the fill Highlight (the Choice model).
  • Reduced motion disables the fill fade.

Do not

  • No div-based stars — the selection, keyboard and form semantics come with the radio group.
  • No display: none on the inputs — they must stay focusable; opacity: 0 over the star box is the contract.
  • No half steps (10 radios) — outside the contract.
  • No flex/grid on the <fieldset> — the fieldset layout trap; plain flow renders identically across engines.
  • No direction: rtl — the fill looks forward through :has().
