Slider

Value selection on a bounded scale on the native <input type="range">: the slider role, keyboard and form participation come with the element. No JS.

Semantic basis

The component is the native range control: the min/max/ step/value model, the slider role, native keyboard (arrows, Home/End, PageUp/PageDown) and :disabled belong to the element. The component only themes the paint: track and thumb through the engine pseudo-elements (the documented Progress paint model) — no state machine.

Canonical markup

<label for="volume">Volume</label>
<span class="ui-slider">
  <input type="range" id="volume" min="0" max="100" value="50" />
</span>

The accessible name is mandatory — a <label> or aria-label (the same host contract as every Field control). The class sits on the wrapper: the value fill must be a real box, and <input> is a void element without ::before/::after to carry one — the probed no-wrapper alternatives both fail (the track pseudo breaks the engine's thumb placement; the thumb can only paint beyond its box through the border-image trick). The input stays a bare native control. The rail fills the container; the box is the hit target and the thumb's air (thumb + 2× space-xs).

Value fill

CSS Anchor Positioning (progressive enhancement): the thumb pseudo is the anchor (anchor-name on the engine thumb pseudo — the engine tracks it natively), the wrapper's ::after paints the fill from the inline-start edge to the thumb's center, the ::before the static gray rail. The fill's rounded cap nests strictly inside the opaque thumb — the junction is invisible. RTL needs no mirror: anchor(end) and the logical insets resolve against the writing mode. Without a resolvable anchor the ::after collapses to zero size: a uniform track, the state carried by the thumb. Zero JS, no host-set value property, no attr().

Vertical

data-orientation="vertical" on the wrapper — writing-mode: sideways-lr on the input: the engine rotates the control. The minimum is at the bottom, the maximum at the top (the mixer convention; the vertical-lr/ vertical-rl modes give min at the top). The wrapper carries the geometry: a definite rail length along its block axis (the --ui-slider-length knob, default 8rem) and the thickness along its inline axis. The fill swaps to the block axis via anchor(top) — direction-independent, no mirror.

Sizes

data-size="sm|lg"; default is md (no attribute). Density only: the thumb scales in fixed steps (16 / 20 / 24px), the rail thickness over the space scale (4 / 8 / 12px) — the Progress density model. The box (thumb + 2× space-xs) stays the hit target at every density.

Customization

The fill follows the brand family by default; the track is the de-emphasised soft surface (the Progress model). Hosts re-theme through the local tokens — no variants, no classes: 

.volume-warning {
  --ui-slider-fill: var(--ui-color-attention);
}

Accessibility

  • The slider role, keyboard and form semantics are native.
  • The accessible name is mandatory (<label> / aria-label).
  • The thumb is solid brand over the surface — the registered Stepper/Avatar pair; the filled segment is border-strong — decorative reinforcement by the border policy (no new APCA pairs).
  • The value is conveyed by the thumb position, not by color alone (WCAG 1.4.1).
  • Forced colors restore the native appearance — the system slider takes over with guaranteed system contrast.
  • Reduced motion — not required, there are no animations.

Do not

  • No div-based widget instead of <input type="range"> — the role, the keyboard and the form semantics come with the element.
  • No unnamed sliders — the accessible name is part of the contract.
  • No host-set value property and no runtime JS for the fill — it follows the thumb natively via CSS Anchor Positioning (the thumb pseudo is the anchor).
  • No datalist tick marks in the contract — the paint is engine-owned and ticks are not themed cross-engine.
