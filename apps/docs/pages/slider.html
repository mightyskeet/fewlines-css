Slider

Value selection on a bounded scale on the native <input type="range">: the slider role, keyboard and form participation come with the element. No JS.

Semantic basis

The component is the native range control: the min/max/ step/value model, the slider role, native keyboard (arrows, Home/End, PageUp/PageDown) and :disabled belong to the element. The component only themes the paint: track and thumb through the engine pseudo-elements (the documented Progress paint model) — no state machine.

Canonical markup

<label for="volume">Volume</label>
<input class="ui-slider" type="range" id="volume" min="0" max="100" value="50" />

The accessible name is mandatory — a <label> or aria-label (the same host contract as every Field control). The rail fills the container; the box is the hit target — 24px at every density (minimum target size).

Value fill (opt-in)

<input class="ui-slider" type="range" min="0" max="100" value="50"
       style="--ui-slider-value: 50" aria-label="Volume">

The filled segment is painted by one gradient token on the track pseudo of both engines (Firefox's ::-moz-range-progress is deliberately not used). CSS cannot read the value attribute and runtime JS is out of contract, so the host sets --ui-slider-value (0–100) next to the attributes — the dual source of truth of the Progress circle: the attributes drive the accessibility tree, the property drives the paint. Without the property the track stays uniform — the state is carried by the thumb, the contract does not break. Hosts with a JS layer sync the property on input — one line.

Vertical

data-orientation="vertical" — writing-mode: sideways-lr: the engine rotates the control and the pseudo chain with it. The minimum is at the bottom, the maximum at the top (the mixer convention; the vertical-lr/ vertical-rl modes give min at the top). The rail length is the --ui-slider-length knob (default 8rem); the gradient mirrors along the new axis automatically.

Sizes

data-size="sm|lg"; default is md (no attribute). Density only: the thumb scales in fixed steps (16 / 20 / 24px), the rail thickness over the space scale (4 / 8 / 12px) — the Progress density model. The hit target stays 24px at every density.

Customization

The fill follows the brand family by default; the track is the de-emphasised soft surface (the Progress model). Hosts re-theme through the local tokens — no variants, no classes: 

.volume-warning {
  --ui-slider-fill: var(--ui-color-attention);
}

Accessibility

  • The slider role, keyboard and form semantics are native.
  • The accessible name is mandatory (<label> / aria-label).
  • The fill/track pair is registered in the APCA matrix as a non-text pair (brand/surface-tint — the Progress pair); the thumb is the Switch thumb model (surface + shared elevation).
  • The value is conveyed by the thumb position, not by color alone (WCAG 1.4.1).
  • Forced colors restore the native appearance — the system slider takes over with guaranteed system contrast.
  • Reduced motion — not required, there are no animations.

Do not

  • No div-based widget instead of <input type="range"> — the role, the keyboard and the form semantics come with the element.
  • No unnamed sliders — the accessible name is part of the contract.
  • Do not set --ui-slider-value beyond 0–100 — the paint does not clamp; the host clamps it.
  • No datalist tick marks in the contract — the paint is engine-owned and ticks are not themed cross-engine.
