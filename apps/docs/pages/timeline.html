Timeline

Chronology of events on the native <ol>: the list semantics, the sequence and the order direction come with the element. The component adds the rail, the marker and the density. Not interactive — no states, no JS.

Semantic basis

The component is the native ordered list: the list/listitem roles come with the elements; the order direction is host-owned (reversed for newest-first, no JS). The component is the rail-and-marker vocabulary, opt-in over the base layer. A stepper (a step-by-step progress with done/current/upcoming states) is a different semantic and a different component.

Canonical markup

<ol class="ui-timeline" role="list">
  <li>
    <p class="ui-timeline-meta">Oct 29, 2026</p>
    <h3>Component shipped</h3>
    <p>The list semantics are native.</p>
  </li>
</ol>

role="list" is insurance for the list-style: none quirk (older VoiceOver dropped the list semantics when the marker was removed; harmless everywhere). The entry content is host-authored: ui-timeline-meta is the optional small line (the fluent role), the rest is plain content — the component only zeroes the outermost margins of the entry's first and last children so the entry box belongs to the list.

Geometry

  1. Oct 29, 2026

    Component shipped

    The marker ring is centered on the rail; the rail is continuous across entries.

  2. Oct 24, 2026

    Typography calibrated

    The entries own the block gap — padding, not margin, so the line never breaks.

The rail is a 2px border on a zero-width pseudo — it survives forced colors (a background strip would not). The marker is a 16px ring on the border-strong token; its opaque surface fill masks the rail passing behind it. All positioning is logical — the layout mirrors itself in RTL.

Customization

The rail is the border token, the ring is the border-strong token — both decorative (the list semantics carry the structure). Hosts re-theme through the local tokens — no variants, no classes: 

.release-timeline {
  --ui-timeline-rail-color: var(--ui-color-brand);
  --ui-timeline-marker-color: var(--ui-color-brand);
}

Accessibility

  • The list roles are native; the order direction is native (reversed). The rail and the marker are decorative by construction — the structure is in the list.
  • The marker ring pair (border-strong on surface) is registered in the APCA matrix as a non-text pair; the rail reuses the divider policy (decorative line, no pair).
  • Forced colors repaint the rail and the ring with the system colors — both are borders.

Do not

  • No <div> grid instead of <ol> — the list semantics are the contract.
  • No stepper semantics here — a stepper (done/current/upcoming with aria-current="step") is a different component.
  • No horizontal variant in markup; the entry margins — density only via data-size.
  • No variant classes — hosts re-theme through the local tokens.
