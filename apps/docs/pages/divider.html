Divider

Thematic break between content sections: line look and margin density on the native <hr>. Static element — no states, no JS.

Semantic basis

The component is the native thematic break: semantics and the separator role come with the element. It is opt-in styling over the base layer — a naked <hr> is already drawn as one border-token line; the class adds the variant vocabulary without a second implementation.

Canonical markup

<hr class="ui-divider" />

The break carries no content — for transitions with text there are headings. Margins belong to the component (data-size); hosts override them with semantic tokens, not classes.

Variants

data-variant="dashed|strong"; default (no attribute) is the solid border-token line. dashed changes only the line style; strong takes the border-strong role — prominence through the color, not a thicker line (a thick hr reads as a rule in data tables, not a break).

Inset

data-inset="start|both" is an orthogonal modifier: it indents the line and combines with any variant. start indents from the logical inline start (mirrored in RTL), the line yields to the leading content column; both indents symmetrically on both sides.

Sizes

data-size="sm|lg"; default is md (no attribute). Density only: the block margins scale over the space scale, the line stays 1px.

Accessibility

  • The separator role is native; the break is decorative by construction — the transition meaning is carried by the surrounding content (headings), never by the line color.
  • No new APCA pairs: the line reuses the validated border roles.
  • Forced colors repaint the border with the system color automatically.

Do not

  • No <div>/<span> instead of <hr> — the native thematic break is the contract.
  • No text or interactive content inside the break.
  • No variant classes — variants are expressed only via data-variant, inset only via data-inset, density only via data-size.
