Avatar

Person/entity identity: photos with an optional presence dot, stacked groups. Static inline element — no states, no JS.

Semantic basis

The platform has no native avatar element, so the component is a static <span> and adds no JS: no role, no focus, no hover. The identity lives in the image's alt — that is the accessible name; a decorative image uses alt="" and the host names the person in surrounding text.

Canonical markup

<span class="ui-avatar"><img src="ada.jpg" alt="Ada Lovelace" /></span>

object-fit: cover crops any source ratio into the circle — the avatar keeps its token square. The image rounds itself (border-radius: inherit), not the container: overflow: hidden would clip the status dot that sits on the circle edge. The surface-tint background shows through while the image loads; a fallback with initials is host styling — the container centers whatever it holds.

Status dot

data-status="online|away|busy" — a dot whose center sits on the circle edge, separated from the image by a page-surface ring. Colors map to the existing families: online — brand, away — border-strong (the gray member, the Timeline marker tone), busy — attention (the system deliberately has no success family). Presence must not rely on color alone (WCAG 1.4.1): the host states it in the accessible name or surrounding text; the dot is decorative.

Sizes

data-size="sm|lg"; default is md (no attribute). Sizes come straight from the fluid space scale: sm = --ui-space-lg, md = --ui-space-xl, lg = --ui-space-2xl. The host resizes declaratively by overriding --ui-avatar-size on any scope — the dot scales with it.

Group

Adjacent avatars stack via a negative margin-inline-start (mirrors in RTL); inside the group every avatar wears a page-surface ring so the overlap reads as separate circles. The group's accessible semantics are the host's — e.g. an aria-label naming the people.

Accessibility

  • Avatar is a generic inline element: no interactive role, not focusable, no states.
  • The accessible name comes from the <img> alt — name the person, not the file.
  • Color is never the only presence signal (WCAG 1.4.1); the dot pairs are validated at the non-text threshold (WCAG 1.4.11) in both themes.

Do not

  • No interactive avatars — a <button> or <a> styled as ui-avatar is out of contract; wrap the avatar in a host link instead.
  • No overflow: hidden on the container — the status dot must reach the circle edge; the image rounds itself.
  • No variant classes — shape and color vocabulary is only data-status and data-size.
  • No widgets inside — badges, chips and counters are siblings of the avatar, not children.
