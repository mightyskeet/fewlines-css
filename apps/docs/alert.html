Alert

Feedback message: informational callout, operation result, error. Static container — the semantic layer (live region role) belongs to the host application.

Semantic basis

The platform has no native alert element, so the component is a static container and adds no JS. For dynamically inserted messages the host adds the role: urgent messages (errors) get role="alert", informational ones role="status". Static callouts need no role.

Canonical markup

<div class="ui-alert" data-variant="success">
  <p class="ui-alert-title">Saved</p>
  <p class="ui-alert-body">Your changes were stored.</p>
</div>

ui-alert-title and ui-alert-body are optional — a short message can be plain text inside ui-alert.

Variants

Heads up

Default variant — info. The attribute is not needed.

Saved

Your changes were stored.

Session expiring

You will be signed out in 5 minutes.

Payment failed

Card was declined. Try another card.

Surfaces come from the tint tokens (--ui-color-*-tint), titles from the bare family colors — both validated by the APCA matrix in both themes.

Host content

Fix 2 validation errors

  • Email is missing an @.
  • Phone must contain digits only.

Lists and paragraphs keep their natural inner spacing; only the box edges are trimmed, so the alert hugs its content.

Accessibility

  • The message text is the accessible name of the live region; role="alert" / role="status" are added by the host for dynamic insertions only.
  • Color is never the only carrier of meaning (WCAG 1.4.1) — the title and message text state the situation.
  • Titles use the bare family colors as the readable variant color on the tint surface.

Do not

  • No interactive elements (buttons, action links) inside alerts — actions belong to Dialog/Popover.
  • No role="alert" on static callouts — live regions announce insertions, not page load.
  • No variant classes — variants are expressed only via data-variant.
