Base typography

The platform's text content elements get one canonical presentation from the base layer: semantic HTML carries the meaning, CSS carries the look. No classes, no states of our own.

Semantic basis

These are native elements (code, kbd, samp, pre, mark, abbr, a, blockquote, hr, sub/sup) styled by bare element selectors in the base cascade layer — below components, so component classes always win. Host applications style nothing for plain text content.

Inline code

Run pnpm build, then press Ctrl+C. The console prints Done in 1.2s.

The family uses --ui-font-mono at 0.875em (scales with the context) on the sunken surface with a border — the same well model as pre; kbd reads as a key cap on the raised surface. Wrapped inline code repeats its padding per line via box-decoration-break: clone — decorative enhancement, the matrix floor Safari needs the -webkit- prefixed form (compatibility notes).

Code block

<pre><code>carries the surface itself;
	a tab renders 4 columns wide.
</code></pre>

The pre element owns the sunken surface, border and scroll; nested code/samp reset automatically, so the canonical <pre><code> pair is not double-padded.

Highlight and abbreviation

The release is relevance-highlighted, built in HTML only.

mark uses the warning tint — the same soft-surface model as Alert/Badge. abbr[title] gets a normalized dotted underline with an explicit thickness and offset (Safari renders none by default, Chromium's is barely visible); the title attribute is the expansion for assistive tech.

Links

Read the overview page next.

Accent color with an underline and a small optical offset; hover deepens to -strong. The visited state is intentionally not restyled. The focus ring comes from the base focus contract.

Quotation and thematic break

A hanging border carries the quotation affordance; text keeps full body contrast.

Content after a thematic break.

blockquote deliberately avoids text-muted: that token pair is calibrated for the fluent role and fails the strict body APCA threshold in the dark theme (tests/apca). hr is a single border-token line.

Subscript and superscript

H2O and x2 never disrupt the surrounding line box.

Baseline-relative positioning (75%, line-height: 0, position: relative) instead of the UA vertical-align, which grows the line height.

Selection

Select any text on this page to see the accent-tint highlight.

::selection paints the accent tint under the author text color — a validated pair; forced-colors modes repaint the selection natively.

Accessibility

  • All color pairs are registered in the APCA matrix: inline code at 0.875em on the fluent role, body text at the body role, both themes.
  • abbr expansion lives in the title attribute — the native contract; color and decoration are not carriers of meaning.
  • Link affordance is not color-only: the underline is always present.
  • Forced colors: links, code surfaces and selection are repainted by the system.

Do not

  • No classes for text content — do not wrap code/mark etc. in ui-* components.
  • No direct --ui-palette-* references when restyling these elements in the host.
  • Do not restyle :visited or remove the link underline — the affordance is part of the contract.
  • Do not put interactive content (<button>, <a>) inside <pre> demos — code blocks are content, not controls.
