Base typography

The platform's text content elements get one canonical presentation from the base layer: semantic HTML carries the meaning, CSS carries the look. No classes, no states of our own.

Semantic basis

These are native elements (code, kbd, samp, var, pre, mark, abbr, a, blockquote (cite), figcaption, hr, sub/sup and the spellcheck pseudo-elements) styled by bare element selectors in the base cascade layer — below components, so component classes always win. Host applications style nothing for plain text content.

Inline code

Run pnpm build, then press Ctrl+C. The console prints Done in 1.2s, and the cache key is userId.

The family uses --ui-font-mono at 0.875em (scales with the context) on the subtle surface with a border — the same well model as pre; kbd reads as an inverted key cap — the brand fill with its on-color. Wrapped inline code repeats its padding per line via box-decoration-break: clone — decorative enhancement, the matrix floor Safari needs the -webkit- prefixed form (compatibility notes).

Code block

</code></pre>

The pre element owns the subtle surface, border and scroll; nested code/samp reset automatically, so the canonical <pre><code> pair is not double-padded.

Highlight and abbreviation

The release is relevance-highlighted, built in HTML only.

mark uses the attention tint — the same soft-surface model as the attention Alert/Badge. abbr[title] gets a normalized dotted underline with an explicit thickness and offset (Safari renders none by default, Chromium's is barely visible); the title attribute is the expansion for assistive tech.

The utility link color with an underline and a small optical offset — independent of the brand family (a re-branded UI keeps blue links unless the host re-themes --ui-color-link). The visited state is intentionally not restyled. The focus ring comes from the base focus contract.

Selection

Select any text on this page to see the selection tint highlight.

::selection paints the utility selection tint under the author text color — a validated pair; forced-colors modes repaint the selection natively.

Figure caption

figcaption renders at the xs caption step in the full --ui-color-text — text-muted fails the strict small APCA threshold (Lc 90) in the dark theme (tests/apca), the same policy as the blockquote body.

Spellcheck

::spelling-error and ::grammar-error repaint the engine's error markers with a wavy --ui-color-attention underline — the urgency tone of validation errors. Progressive enhancement (compatibility notes): Chrome 121+ and Safari 17.4+ take the custom look; without support the rule is ignored and the native squiggle stays. The demo needs a browser dictionary for English.

Fluid scale

The heading ladder above rides the fluid scale: sizes interpolate with the viewport width (progress() + pow(), compatibility notes), pinning outside the --ui-fluid-vmin…--ui-fluid-vmax window. Every h1–h6 pairs its scale step with an explicit weight and line height — the canonical mapping lives in theme notes; there are no typographic classes: positions without a matching element are set from the step tokens directly.

Accessibility

  • All color pairs are registered in the APCA matrix: inline code at 0.875em on the fluent role, body text at the body role, both themes.
  • abbr expansion lives in the title attribute — the native contract; color and decoration are not carriers of meaning.
  • Link affordance is not color-only: the underline is always present.
  • Forced colors: links, code surfaces and selection are repainted by the system.

Do not

  • No component classes for text content — do not wrap code/mark etc. in ui-* components; there are no typographic classes — positions without a matching element are set from the step tokens (theme notes).
  • Do not set xs-step fine print in --ui-color-text-muted — the muted pair fails the small APCA threshold (Lc 90) in the dark theme.
  • No direct --ui-palette-* references when restyling these elements in the host.
  • Do not restyle :visited or remove the link underline — the affordance is part of the contract.
  • Do not put interactive content (<button>, <a>) inside <pre> demos — code blocks are content, not controls.
