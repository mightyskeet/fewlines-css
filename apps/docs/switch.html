Switch

Binary on/off choice: settings, consents, modes. Native checkbox behavior — no JS.

Native basis

<input type="checkbox"> — native toggle, keyboard (Space) and form participation. The switch attribute upgrades the exposed role to switch where supported (Safari 17.4+ today); in other engines the control is a native checkbox with identical behavior. The track and thumb are drawn with appearance: none.

Canonical markup

<label class="ui-switch-field">
  <input class="ui-switch" type="checkbox" switch />
  <span class="ui-switch-label">Email notifications</span>
</label>

The wrapper is an implicit label — clicking the text toggles the control. The label text is the accessible name and must not be removed. Stacked switches get spacing automatically.

States

States come from the platform: :checked, :hover, :disabled. On state uses the accent surface token; the thumb position — not color alone — carries the state (WCAG 1.4.1).

Required consent

Submit the empty form: the danger border appears only after interaction (:user-invalid, same intent gate as inputs).

Accessibility

  • Role is switch in engines with attribute support, native checkbox elsewhere — both are valid on/off roles. Hosts wanting a uniform role today can add role="switch" (native ARIA, no JS).
  • Space toggles natively; the focus ring comes from the base layer.
  • Hints: host adds an element and links it via aria-describedby.

Do not

  • No div/button role="switch" + JS emulation — native state, keyboard and forms are lost.
  • No :invalid styling without :user- (Field rule).
  • No size/variant classes — the canonical view is one.
