Accordion

Disclosure widget: FAQ, settings, grouped content. Open/close is native — no JS.

Native basis

<details>/<summary> — native disclosure widget; details[open] is the native state attribute; Enter/Space toggles natively. Expand/collapse animation is on by default via ::details-content + animated grid tracks (minmax(0, 0fr) → minmax(0, 1fr)) — it works in all engines that support ::details-content (Chrome 131+, Firefox 143+, Safari 18.4+); without it the content appears instantly.

Canonical markup

<details class="ui-accordion">
  <summary class="ui-accordion-summary">Title</summary>
  <div class="ui-accordion-content">Content</div>
</details>

What is @fewlines/css?

A platform-native UI system: semantic HTML, modern CSS, zero runtime JS.

Is JavaScript required?

No. Open/close, keyboard behavior and accessibility are native.

Open by default

The native open attribute controls the initial state.

Stacked accordions get dividers and shared rounding automatically via the adjacent sibling selector.

Exclusive accordion

Option A

Only one of these can be open.

Option B

Opening one closes the other.

The native name attribute on <details> makes the group exclusive — core adds nothing. When switching, one block closes while the other opens: both animate simultaneously, so the content below does not flicker.

Accessibility

  • Disclosure role is native; the accessible name comes from <summary>.
  • Enter/Space toggles natively — no keyboard JS.
  • aria-expanded is not needed — state is read from the native open.

Do not

  • No div + JS toggle emulation — native state and keyboard behavior are lost.
  • No JS for open/close — <details> handles it.
  • Never remove <summary> — without it the widget does not expand.
