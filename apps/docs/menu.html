Menu

A list of actions in an overlay: the native <menu> element inside the popover shell. Opening, placement, light dismiss and Escape come with the platform; the menu is only the list vocabulary on top.

Semantic basis

<menu> is the platform's unordered list of actions — the list semantics and the separator role of <hr> come with the elements. The menu itself is a popover: it composes with ui-popover (one canonical shell — surface, elevation, anchor placement, the open/close motion). No ARIA role substitution: role="menu"/menuitem would promise arrow-key navigation and a roving tabindex that pure CSS cannot deliver. The items stay plain buttons and links; hosts that need the ARIA menu pattern add it in their own JS layer.

Canonical markup

<button class="ui-button ui-popover-trigger" type="button" popovertarget="file-menu">
  Actions
</button>

<menu class="ui-popover ui-menu" id="file-menu" popover>
  <li>
    <button class="ui-menu-item" type="button" command="hide-popover" commandfor="file-menu">
      Rename
    </button>
  </li>
  <li><hr class="ui-divider" /></li>
  <li>
    <button class="ui-menu-item" type="button" data-variant="attention"
            command="hide-popover" commandfor="file-menu">
      Delete
    </button>
  </li>
</menu>

class="ui-popover ui-menu": the shell (surface, placement data-block/data-inline, motion) is the Popover component; the menu adds the list and item styles. Closing after an action is native — Invoker Commands (command="hide-popover" + commandfor): the click event still fires after the command, so the host JS layer runs its own action. Engines without the attribute simply keep the menu open.

    Placement

    The menu is positioned by the Popover component — the shell is the popover, so the placement vocabulary applies unchanged and the menu adds none of its own. Set data-block / data-inline on the menu with the position-area keywords per axis: above the trigger (data-block="block-start"), at the sides (data-inline="inline-start" / data-inline="inline-end"), corners combine both, and the span-* keywords pin the menu flush to the trigger's edge. Without attributes the menu opens below the trigger and flips above on overflow. Anchoring needs the trigger to carry ui-popover-trigger; several trigger/menu pairs on one page must scope the anchor names (anchor-scope: all on a common wrapper). There is no collision handling — if the chosen side does not fit, pick the other side explicitly. The Popover page shows all nine placement cells.

    Customization

    .compact-menu {
  --ui-menu-gap: var(--ui-space-3xs);
  --ui-menu-min-inline-size: 10rem;
}

.shell-menu {
  max-inline-size: 24rem; /* Popover's shell cap */
}

    The list rhythm (--ui-menu-gap) and the minimum width (--ui-menu-min-inline-size) are the menu's own local tokens; the shell overrides (surface, elevation, max-inline-size) belong to the Popover component.

    Accessibility

    • The menu announces as a list of actions: <menu> is a list, items are buttons and links with their labels, the separator is the native <hr> (separator role).
    • Tab between items, Enter/Space activate <button>, Enter activates <a>; Escape and an outside click close the menu natively.
    • autofocus on the first item moves focus into the menu on open; closing returns focus to the trigger (native popover behavior).
    • Disabled items are native <button disabled> — out of the tab order; a disabled link uses aria-disabled="true".
    • The APCA pairs are existing registrations: text/attention on surface-raised and the attention/attention-tint hover fill (the Alert pair).

    Do not

    • No role="menu"/menuitem — the roles promise arrow-key navigation and a roving tabindex that pure CSS cannot deliver.
    • No items without <li> — the <menu> content model only allows list items.
    • No JS for opening/closing in the core — popovertarget, command and light dismiss are native; a host JS layer can add the arrow-key menu pattern.
    • command="close"/request-close are dialog commands — the popover target takes command="hide-popover".
