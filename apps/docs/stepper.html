Stepper

Step-by-step progress of a process on the native <ol>: the step sequence comes with the element, the current step is the native aria-current="step" state, the done state is a host-declared data-done attribute. Steps may be links. No JS.

Semantic basis

The component is the native ordered list plus the native ARIA step state: aria-current="step" marks the current step and is announced by screen readers. The platform has no "completed" attribute, so the host declares done steps with the boolean data-done attribute — the same host-declared vocabulary as data-variant. Upcoming steps carry no attributes. A stepper is not a timeline: a timeline is a static chronology of events, the stepper carries the done/current/upcoming progress of a process. The visual vocabulary (markers, rail) is shared.

Canonical markup

<ol class="ui-stepper" role="list">
  <li data-done><a href="/cart">Cart</a></li>
  <li aria-current="step"><a href="/checkout">Checkout</a></li>
  <li>Review</li>
</ol>

role="list" is insurance for the list-style: none quirk (the timeline precedent). Interactive steps are <a href> elements inside the <li>; static steps are plain text or any host element. The state attributes live on the <li> or on the step's interactive child — the CSS honors both. The step content is host-authored: a label, a number, a description — the component only zeroes the outermost margins of the entry's first and last children.

States

  1. Cart
  2. Checkout
  3. Review

The marker carries the state by shape, not by color alone (WCAG 1.4.1): done is a solid accent disc, current is an accent ring with a dot, upcoming is the hollow ring. The opaque fills mask the rail passing behind the marker.

Orientation

  1. Cart
  2. Checkout
  3. Review

The default orientation is vertical (the timeline sibling geometry) — the marker is centered exactly on the content's first line (the lh unit; a host heading as the first child carries its own metrics and is re-aligned through the local token). data-orientation="horizontal" is the classic wizard row: equal columns, the marker on top, the label centered below, a continuous line between the marker centers. All positioning is logical — the layout mirrors itself in RTL.

Customization

The accent is the brand token; the upcoming ring is border-strong, the rail is border — both decorative (the semantics stay in the list and aria-current). Hosts re-theme through the local tokens — no variants, no classes: 

.onboarding-steps {
  --ui-stepper-accent: var(--ui-color-attention);
  --ui-stepper-gap-block: var(--ui-space-md);
}

Accessibility

  • The list roles are native; the current step is the native aria-current="step" state.
  • The done state is not announced by screen readers (the platform has no such attribute) — hosts that need it add their own text or visually hidden note.
  • The state is carried by the marker shape, not by color alone (WCAG 1.4.1). The brand on surface marker pairs are registered in the APCA matrix as non-text pairs; the rail reuses the divider policy (decorative line, no pair).
  • Forced colors repaint the rails and the rings with the system colors — both are borders; the gradient dot and the disc fill are stripped to the system canvas.

Do not

  • No <div> grid instead of <ol> — the list semantics are the contract.
  • No chronology of events here — a timeline is a different component (Timeline).
  • No data-done and aria-current="step" on the same step; no state classes (.is-done and friends) — attributes only.
  • No entry margins for density — the inter-step rhythm belongs to the local tokens.
