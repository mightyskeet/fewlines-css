Popover

Non-modal overlay: menus, tooltips, small panels. Light dismiss and Escape are native.

Native basis

Popover API: popover attribute; declarative trigger popovertarget; popovertargetaction="show|hide|toggle"; :popover-open; native light dismiss and Escape; native top-layer; implicit anchor from popovertarget (Chrome 133+, FF 147+, Safari 26+).

Canonical markup

<button class="ui-button ui-popover-trigger" type="button" popovertarget="p1">
  Options
</button>

<div class="ui-popover" id="p1" popover>
  <p>Popover content</p>
</div>

ui-popover-trigger on the trigger is optional — it enables anchor positioning (declares anchor-name).

Live example

Anchor-positioned popover (fallback: centered). Click outside or Escape closes it.

Positioning

  • With anchor support: below the trigger (position-area: block-end center), fallback above.
  • Without anchor support: centered in the viewport (fixed).
  • Anchor contract: anchor name --ui-popover-anchor; no collision handling — host sets position-area when needed (see the placement grid below).

Placement grid

position-area selects one of nine regions of the 3×3 grid built around the trigger — logical keywords; a lone center means centered over the trigger in both axes. The default is block-end center. Once position-area applies, auto margins resolve to zero and the popover aligns toward the anchor, so the demo adds a uniform margin for breathing room.

Each pair declares its own anchor-name — with a shared name the last trigger in DOM order would anchor every popover — plus explicit position-anchor and position-area, and position-try-fallbacks: none to keep the placement exact. Real UIs define fallbacks for edge cases instead.

Edge-aligned placement

The span-* keywords extend the region away from the trigger while the default alignment keeps the popover hugging it — the result is flush with one edge of the trigger, the classic menu/tooltip alignment. Verified in Chromium; other engines follow the same grammar (compatibility notes).

Accessibility

  • Role and semantics come natively from the Popover API.
  • Light dismiss and Escape are native — no JS.
  • Focus is not trapped (non-modal) — native behavior.

Do not

  • No div + JS toggle emulation — light dismiss, Escape and top-layer are lost.
  • No position-visibility: anchor-valid/visible — outside the browser matrix.
  • No modal popover — for modality there is Dialog.
