# Compatibility decisions

Source of truth для решений о совместимости platform features. Каждое решение
получено через Can I Use MCP (`caniuse_feature` + `browserslist_compatibility_check`),
не по памяти. Дата аудита: 2026-10-01.

## Browser matrix

Контракт: `.browserslistrc` в корне репозитория — `last 2 versions, not dead`.
Floor не снижается ради удобства реализации отдельной фичи.

Фактическая матрица на дату аудита: Chrome 153–154, Edge 153–154, Firefox 155–156,
Safari 26.6–27, iOS Safari 26.6–27, Android Chrome 154 и экосистемные браузеры.
Каждая platform feature проходит аудит через Can I Use MCP; решения
(direct use / progressive enhancement) фиксируются в этом документе с датой
(см. «Процедуру обновления»).

## Ключевые решения подробно

### Docs-site chrome (apps/docs) — Grid + sticky сайдбар

Аудит 2026-10-02 (Can I Use MCP, `caniuse_feature` + `browserslist_compatibility_check`
против `.browserslistrc`): классическая docs-раскладка демо-сайта — sticky-сайдбар
(бренд, навигация, theme toggle) + контентная колонка через CSS Grid на `body`.

- CSS Grid (`css-grid`): Chrome 58, FF 54, Safari 10.1 — **direct use**, floor
  матрицы (Chrome/Edge 153+, FF 155+, Safari 26.6+) значительно выше.
- `position: sticky` (`css-sticky`): полный Chrome 91+, FF 59+, Safari 13+;
  единственные partial-версии касаются table-элементов (`thead`/`tr`) — не
  релевантно для grid-item сайдбара. **direct use**.
- Narrow-экраны (< 72rem): mobile-first раскладка без grid — сайдбар как
  обычная шапка (flex wrap), sticky не применяется. Деградация безопасная:
  без grid/sticky контент остаётся в потоке.

### CSS Anchor Positioning — progressive enhancement

Поддержка **partial** во всей целевой матрице:

- Chrome/Edge 125+: нет `position-visibility: anchor-valid` / `anchor-visible`;
- Firefox 147+: нет анимации `anchor()` / `anchor-size()`;
- Safari 26.0: нет `position-anchor: normal`; полная поддержка с 27.

Правила использования:

1. Popover обязан корректно работать **без** anchor positioning (обычное CSS
   positioning как база).
2. Anchor-улучшение оборачивается в `@supports (anchor-name: --ui-anchor-test)`.
3. Запрещено полагаться на `position-visibility: anchor-valid` / `anchor-visible`
   и на анимацию `anchor()` — эти подфичи не покрыты матрицей.
4. Anchor contract (имена якорей, fallback positions, ограничения collision
   handling) документируется в contract-доке компонента Popover.

### `accent-color` — partial в Safari

Safari 15.4–26.1 не поддерживает минимальный контраст акцентного контрола
(WebKit bug 244233). Решение: использовать `accent-color: var(--ui-color-accent)`,
но не считать UA-контраст достаточным — контролы с accent попадают в APCA-аудит.

### Relative color syntax — без ограничений

Partial-версии (Chrome 119–130, Firefox 128–132) с ограничением на `currentcolor`
и system color keywords лежат **ниже floor матрицы** (`last 2 versions`): целевые
Chrome 153+, Firefox 155+ поддерживают relative color syntax полностью, включая
`currentcolor`. Ограничений на использование нет.

### `sign()`/`round()` в `calc()` — без ограничений (аудит 2026-10-30)

Используются в токен-деривации (`tokens/derive.css`): бинарный выбор ветки
заливки по светлоте seed (`sign()` + `round(nearest)` — прыжок через мёртвую
зону APCA). Поддержка: `sign()` — Chrome 138, Firefox 118, Safari 15.4;
`round()` — Chrome 125, Firefox 118, Safari 17.2 (web-features `wf-abs-sign`,
`wf-round-mod-rem`, проверка 2026-10-30). Все partial-версии ниже floor
матрицы — **direct use**, ограничений нет.

### `contrast-color()` — сознательно не используется (аудит 2026-10-30)

Поддержка: Chrome 147, Firefox 146, Safari 26 (`wf-contrast-color`) — ниже
floor, но даже при полноте поддержки функция **не подходит** для полюсов
`on-*`: её выбор контрастного полюса ориентирован на WCAG и в зоне светлоты
Y ≈ 0.18–0.32 расходится с APCA-выбором (прототип `adaptive-colors`,
находка 2026-10-26). Полюса задаются формулой ветки в derive-слое.

### `field-sizing` — enhancement

Отсутствует в Safari до 26.2. Использовать только внутри `@supports`; компонент
Field обязан быть пригодным без него.

Правила применения (2026-10-01):

- `ui-textarea` — авторазмер **по умолчанию** внутри `@supports`:
  `field-sizing: content`, границы `min-block-size: 3lh` / `max-block-size: 50vh`,
  `overflow: auto`. Opt-out: `data-field-sizing="fixed"`. Без поддержки
  `field-sizing` — фиксированный размер от `rows` (контрол полностью пригоден);
- `ui-input` — авторазмер по opt-in: `data-field-sizing="content"`.

### `position-area`: ключевые слова `span-*`

Уточнение записи от 2026-10-01 (браузер-проба 2026-10-02, Chromium
153.0.8010.12 / Playwright):

- Голое ключевое слово `span-inline` **не существует в грамматике**
  css-anchor-position-1 §3.1.2 (для inline-оси есть только
  `span-inline-start` / `span-inline-end` / `span-all`) — поэтому
  `block-end span-inline` инвалидируется; старая запись относилась
  именно к нему, а не к `span-inline-*`;
- `block-end span-inline-start` и `block-end span-inline-end` —
  **валидны и работают** (computed `end span-start` / `end span-end`).
  `block-end span-inline-end` даёт «менюное» размещение: окно под
  триггером, левые края вровень (выравнивание по умолчанию — к якорю,
  css-anchor-position-1 §4.1);
- Физические `span-left` / `span-right` в Chromium 153
  **инвалидируются** (computed `none`) — использовать только логические
  ключевые слова;
- При переполнении области окно «сдвигается», оставаясь во viewport
  (unsafe alignment по умолчанию);
- Матрица (браузер-проба 2026-10-02, Playwright): все 8 логических
  `span-*` значений парсятся и работают в Chromium 153.0.8010.12,
  Firefox 155.0, WebKit 26.6; геометрия «впритык» совпадает во всех
  трёх движках.

Решение: в компоненте Popover логические `span-*` разрешены — размещение
задаётся через `data-block` / `data-inline` на popover (значения —
ключевые слова `position-area` как есть, оси компонуются через custom
properties); физические `span-left/right` и голое `span-inline` не
использовать. Default без атрибутов — `block-end center` →
`block-start center`.

### Tooltip: `popover="hint"` + interest invokers (2026-10-02)

Аудит (Can I Use MCP, `caniuse_feature` + `browserslist_compatibility_check`
против `.browserslistrc`):

- `popover="hint"` (`wf-popover-hint`): Chrome/Edge 151+, FF 153+; Safari —
  только preview. Baseline: false;
- interest invokers (`interestfor`, `wf-interest-invokers`): Chrome/Edge
  142+; Firefox и Safari — не поддерживают;
- Popover API (`wf-popover`) — direct use (см. сводную таблицу).

Решения (компонент Tooltip):

1. `popover="hint"` в канонической разметке — **progressive enhancement**:
   в движках без keyword значение невалидно и по invalid-value default
   деградирует до состояния `auto` — элемент остаётся полноценным
   dismissible popover.
2. `interestfor` на триггере — **progressive enhancement**: hover/focus
   активация в Chromium/Edge. В движках без interest подсказка **не имеет
   hover-активации по замыслу** — сужение до native части (docs/architecture.md,
   Native first): описание остаётся связано через `aria-describedby`, клик остаётся
   действием триггера.
3. `popovertarget` (+ `popovertargetaction="show"`) — **не канонический
   атрибут**, opt-in только для инертных триггеров (кнопки «?»): пробой
   показал, что на триггерах-действиях клик-fallback связывает подсказку
   с действием (submit побеждает и подсказка не открывается; type="button"
   — действие выполняется и подсказка показывается); на инертных триггерах
   работает во всех трёх движках. `show` вместо default toggle — чтобы
   повторный клик не закрывал подсказку.
4. Роль `tooltip` явно не задаётся — неявная минимальная роль у
   `popover="hint"`; host может добавить `role="tooltip"` для движков вне
   матрицы (тот же паттерн, что у Switch).
5. Позиционирование — как у Popover: CSS Anchor Positioning внутри
   `@supports`, без него центрирование; collision handling не предоставляется.

Обновление 2026-10-04: решение 2 («без hover-активации по замыслу») заменено
CSS-фоллбеком активации — см. раздел «Tooltip: CSS-фоллбек активации без
interest» ниже.

### Tooltip: CSS-фоллбек активации без interest (2026-10-04)

Аудит (Can I Use MCP, `caniuse_feature` + `browserslist_compatibility_check`
против `.browserslistrc`):

- `:interest-source` / `:interest-target` (`mdn-css_selectors_interest-source`):
  Chrome/Edge 142+; Firefox 156/157 и Safari 26.6/27 — не поддерживают.
  Псевдоклассы валидны только в движках с interest invokers ⇒ форма
  `@supports not selector(:interest-source)` — надёжный CSS-детектор:
  гейт активен в FF/Safari, выключен в Chromium/Edge;
- media-фичи `hover`/`pointer` (`css-media-interaction`): Chrome 41, FF 64,
  Safari 9 — **direct use** (guard от sticky-hover на таче).

Браузер-проба (2026-10-04, Playwright: Chromium 153, Firefox 155, WebKit 26.6):

| Поведение                                                               | Chromium            | Firefox                  | WebKit                   |
| ----------------------------------------------------------------------- | ------------------- | ------------------------ | ------------------------ |
| `CSS.supports('selector(:interest-source)')`                            | true                | false                    | false                    |
| hover открывает подсказку                                               | да (interest)       | да (CSS-shown)           | да (CSS-shown)           |
| CSS-shown подсказка — `:popover-open`                                   | —                   | нет                      | нет                      |
| focus открывает, blur закрывает                                         | да (interest)       | да (`:focus-visible`)    | да                       |
| anchor-размещение у CSS-shown (below, overlap, in viewport)             | —                   | да                       | да                       |
| переход указателя через зазор не закрывает подсказку                    | — (native interest) | да (мост + граница)      | да                       |

| выходная анимация CSS-shown (opacity/translate transitionrun)           | —                   | да                       | да                       |

Попутные пробы (та же сессия):

- псевдоэлементы (`::before`) anchor-positioned подсказки **не участвуют в
  хит-тесте** в Firefox и WebKit (контроль: псевдоэлемент обычного
  позиционированного элемента хит-тестится в обоих) ⇒ мост перенесён на
  триггер (`::after` + `position: relative` на триггере);
- `anchor-scope: all` на обёртке пары создаёт **stacking context**: z-index
  подсказки заперт внутри обёртки, контент следующих пар побеждает хит-тест.
  Решение — подъём обёртки через `:has(> …)` на состояния показа
  (`position: relative; z-index: 2`) + `z-index: 1` на подсказке;
- зазор размещения перенесён с `margin-block-start` на прозрачную верхнюю
  границу подсказки (часть её hit box): переход указателя не имеет мёртвой
  зоны и не зависит от фазы входной/выходной анимации (мост держит
  `:hover` триггера, граница — `:hover` подсказки).

Решения (компонент Tooltip, фоллбек):

1. Гейт — единственный, `@supports not selector(:interest-source)`;
   внутри — базовый (центрирование) и anchor-режимы, как у popover-пути.
2. Показ: `:hover` (только `@media (hover: hover) and (pointer: fine)`) и
   `:focus-visible` на триггере; удержание — `:hover` на самой подсказке.
   Анимация входа/выхода — та же (`@starting-style` + `allow-discrete`);
   выход анимируется во всех движках (top layer не участвует).
3. Принятые ограничения (осознанно, ради видимости подсказок):
   Escape не закрывает CSS-shown подсказку (WCAG 1.4.13 dismissible
   нарушается в fallback-движках; закрывается уходом указателя/blur);
   подсказка не в top layer — предок с `transform`/`filter`/`contain` может
   обрезать; контент с явным z-index выше 1 перекрывает.
4. `popovertarget`-opt-in не меняется; задержки `interest-delay-*` в
   фоллбеке не воспроизводятся (показ мгновенный).

### Overlay-контракт: viewport-единицы и центрированный fallback (2026-10-15)

Аудит по итогам ревью (Can I Use MCP, `caniuse_feature`):

- `dvw`/`dvh` (`viewport-unit-variants`): Chrome 108, FF 101, Safari 15.4 —
  **direct use**, floor матрицы выше. `dvw` резолвится против initial
  containing block — без классического скроллбара, в отличие от `100vw`
  (тот же контракт, что у Drawer: `drawer.md` запрещает viewport-единицы
  для ширины). Применение: `min(90dvw, 32rem)` в Dialog,
  `calc(100dvw - 2 * var(--ui-space-2xl))` в Popover — замена `vw`.

Браузер-проба находки 16 (2026-10-15, Playwright: Chromium 153, Firefox 155,
WebKit 26.6): popover с implicit anchor (`popovertarget`) и правилами
центрированного фоллбека (`position: fixed; inset: unset; inset-*: 50%;
translate: -50% -50%`) — во всех трёх движках центрируется в viewport
(popLeft = expectedCenteredLeft во всех), к implicit anchor не цепляется.
Подозрение из аудита не подтвердилось; изменений не требует.

### Universal/типизированный `attr()` (css-values-5) — вне матрицы

Can I Use MCP (2026-10-02): Chrome 133+, Edge 133+, Firefox 155+;
Safari 27.0 / 27.1 — **не поддерживается** (только TP). Использовать
нельзя.

Когда universal `attr()` войдёт в матрицу: десять правил-идентичностей
`data-block` / `data-inline` в компоненте Popover сворачиваются в
`attr(data-block type(<position-area>))` /
`attr(data-inline type(<position-area>))` с fallback `span-all`.

### `anchor-scope: all` — связывание нескольких пар триггер/popover

Can I Use MCP (MDN-данные, проверено 2026-10-02): Chrome 131+, FF 147+,
Safari 26+ — внутри матрицы.

Браузер-проба (2026-10-02, Playwright): `anchor-scope: all` на общем
предке пары корректно ограничивает поиск якоря своим поддеревом во всех
трёх движках матрицы — каждая пара «триггер + popover» связывается через
общее имя `--ui-popover-anchor` без уникальных имён (без скоупа все
popover привязываются к последнему триггеру в DOM,
css-anchor-position-1 §2.3).

Решение: несколько пар на странице — `anchor-scope: all` на общем
предке пары (используется в docs-демо popover) либо уникальное имя
якоря на каждую пару.

### Анимация `<details>` — `::details-content` + grid track animation

Аудит 2026-10-01 (Can I Use MCP):

- `::details-content` — Chrome 131+, FF 143+, Safari 18.4+ (partial:
  Safari не поддерживает чейнинг псевдоэлементов после него, WebKit bug
  283446 — не полагаться на `::details-content::before` и т.п.);
- grid track animation (`grid-template-rows` интерполируется между
  треками) — Chrome 107+, FF 66+, Safari 16+, baseline high — **direct
  use** во всей целевой матрице;
- `interpolate-size: allow-keywords` — Chrome/Edge 129+, Firefox и Safari
  не поддерживают — **в компоненте не используется** (решение от
  2026-10-01, см. ниже).

Правила применения (компонент Accordion):

1. Анимация раскрытия — на `::details-content` внутри единственного gate
   `@supports selector(::details-content)`; движок с поддержкой
   псевдоэлемента всегда имеет и анимацию grid-треков (её floor ниже).
2. Высота контента анимируется через grid-трек:
   `grid-template-rows: minmax(0, 0fr) ↔ minmax(0, 1fr)`.
   Форма `minmax(0, …)` **обязательна**: трек `0fr` имеет min-content
   минимум, поэтому padding элемента контента не даёт треку схлопнуться —
   при открытии первый кадр начинается с фантомной высоты (прыжок), при
   закрытии в конце остаётся щелчок. Проверено покадрово в Firefox и
   Chromium (2026-10-01): с `minmax(0, …)` максимальный шаг кадра ≤3px на
   130px, без него — до 16px скачок на границах анимации.
3. `content-visibility … allow-discrete` сглаживает нативный дискретный
   переход hidden→visible; `@starting-style` задаёт from-state для
   открытия; закрытие анимируется обычным transition к `minmax(0, 0fr)`.
4. UA-стили закрытого `::details-content` (`content-visibility: hidden`)
   не переопределяются — они дают нулевую высоту в покое.
5. Без `::details-content` — контент появляется/исчезает мгновенно,
   компонент полностью пригоден (graceful degradation внутри единственной
   реализации).
6. `interpolate-size`-подход (`block-size: 0 ↔ auto` на
   `::details-content`) отклонён: работает только в Chrome/Edge, а без
   `interpolate-size` переключение щёлкает на 50% длительности.

### Base typography — текстовые элементы (2026-10-03)

Аудит (Can I Use MCP, `caniuse_feature` + `browserslist_compatibility_check`
против `.browserslistrc`) для расширения `base/typography.css` на семантические
текстовые элементы (`code`, `kbd`, `samp`, `pre`, `mark`, `abbr`, `a`,
`blockquote`, `hr`, `sub`/`sup`, `::selection`):

- `tab-size` (`css3-tabsize`), значение `<integer>`: Chrome 42+, FF 91+,
  Safari 13.1+ — **direct use**, floor матрицы значительно выше
  (`<length>`-значения не используются);
- стилизация `text-decoration` (`text-decoration`): dotted-подчёркивание —
  Chrome 57+, FF 6+, Safari 8+; `text-underline-offset` — Chrome 87+, FF 70+,
  Safari 12.1+; `text-decoration-thickness` — Chrome 89, FF 70, Safari 12.1;
  `text-decoration-skip-ink` — Chrome 64+, FF 70+, Safari 15.4+ —
  **direct use**. Partial-ноты caniuse относятся только к устаревшему
  `text-decoration-skip` (deprecated) — не используются;
- `box-decoration-break: clone` (`css-boxdecorationbreak`): Chrome/Edge 130+,
  FF 32+ — unprefixed; **Safari floor (26.6) и 27.x — только
  `-webkit-box-decoration-break`** (prefixed, работает для inline-элементов) —
  **progressive enhancement**: декларативная пара prefixed + unprefixed
  (Chromium принимает обе). Улучшение декоративное: повторение паддинга/радиуса
  на фрагментах переносимого inline-кода; без поддержки код полностью читаем;
  `@supports`-гейт не нужен (поддержка value-формы не детектируется надёжно,
  а пара форм безвредна);
- `::selection`: universal (вне версионного caniuse-трекинга) — **direct use**;
  в forced-colors режимах выделение перекрашивается системно.

Решения (base typography):

1. Селекторы — голые элементы в base layer (ниже компонентов): компонентные
   классы всегда переопределяют. Никаких классов для текстовых элементов.
2. Inline-семейство `code`/`kbd`/`samp` — `--ui-font-mono`, `0.875em`
   (масштабируется с контекстом), sunken-поверхность; `kbd` — инвертированная
   клавиша: fill `neutral-surface`, текст `on-neutral`, без бордера
   (2026-10-27: различение с `code`, пара `on-neutral/neutral-surface`).
   Пары зарегистрированы в APCA-реестре на fluent-роли (`text/surface-sunken`,
   `text/surface-raised`); pre — существующая body-пара `text/surface-sunken`.
3. `pre :is(code, kbd, samp)` — сброс inline-оформления: каноническая пара
   `<pre><code>` не получает двойной паддинг и двойное уменьшение шрифта.
4. `mark` — warning-tint + `text` (существующая body-пара `text/warning-tint`,
   та же мягкая поверхность, что Alert/Badge). [Устарело 2026-10-28:
   warning удалён — `mark` переехал на `surface-tint` / `text`, пара
   `text/surface-tint`. Устарело 2026-10-29: `mark` переехал на
   `attention-tint` / `text` — та же мягкая поверхность, что attention
   Alert/Badge; пара `text/attention-tint` уже валидирована в Alert.]
5. `blockquote` — текст **полного контраста** (`text`), а не `text-muted`:
   проверка показала, что `text-muted/surface` в тёмной теме даёт Lc 63.5 —
   ниже body-порога 75 (пара откалибрована под fluent); «кавычность» несёт
   висячий бордер. Новая body-пара в реестр не добавлялась.
6. `sub`/`sup` — baseline-relative позиционирование (75%, `line-height: 0`,
   `position: relative`): смещение не раздувает межстрочный интервал, в отличие
   от UA `vertical-align: sub/super`.

### Drawer (2026-10-03)

Аудит (Can I Use MCP, `caniuse_feature` + `browserslist_compatibility_check`
против `.browserslistrc`):

- Popover API (`wf-popover`): Chrome 116, FF 125, Safari 17, iOS Safari 18.3 —
  **direct use** (запись 2026-10-01). MDN-нота: iOS Safari 17–18.2 — light
  dismiss partial (webkit.org/b/267688) — ниже floor матрицы (iOS 26.6+),
  ограничение не релевантно;
- `::backdrop` на popover (`mdn-css_selectors_backdrop_popover`): Chrome 114+,
  Edge 114+, FF 125+, Safari/iOS 17+ — **direct use**, floor матрицы выше.
  Новая запись сводной таблицы: Drawer — первый компонент, использующий
  `::backdrop` popover (скрим по умолчанию, как у Dialog; host может
  переопределить или убрать);
- `@starting-style` + `transition-behavior: allow-discrete` — **direct use**
  (записи 2026-10-01); `overlay` transition — та же группа, graceful
  degradation без анимации;
- CSS Anchor Positioning — не используется: панель прижата к краю viewport,
  размещение не зависит от триггера.

Решения (компонент Drawer):

1. База — `popover` (auto) на semantic-элементе host: top-layer, light
   dismiss, Escape и декларативный `popovertarget` — нативно, без JS.
   Режим **только немодальный** (страница интерактивна, фокус не
   захватывается); блокирующие панели — Dialog (modal-only, см. dialog.md).
2. Геометрия — `inset-block: 0` + `block-size: auto` (растяжение против UA
   `height: fit-content`), ширина `min(24rem, 100%)`: процент резолвится
   против initial containing block — без классического скроллбара, в отличие
   от `100vw`. Края — логические `inset-inline`; варианты
   `drawer-start` (default) / `drawer-end`; радиус только на внутреннем крае.
3. Фокус в панель — нативный `autofocus` внутри popover (show-шаги выполняют
   focusing steps); возврат фокуса на триггер при закрытии — host.
4. Скрим — по умолчанию как у Dialog (`color-mix`, фейдится в обе стороны,
   решение 2026-10-03 после первого ревью): клик по скриму закрывает панель
   (light dismiss) и доходит до элемента под ней; семантика остаётся
   немодальной (нет focus trap) — для настоящей блокировки есть Dialog.
   Host может переопределить/убрать скрим через `::backdrop`. Скролл-лок —
   host: `body:has(#id:popover-open)`.
5. Анимация выхода (обратный переход, 2026-10-03): transition объявлен на
   элементе без привязки к open-состоянию, hidden-state живёт в базовых
   стилях, вход якорится `@starting-style`. Браузер-проба (Playwright,
   2026-10-03, Chromium/Firefox/WebKit):

   | Поведение                             | Chromium                    | Firefox       | WebKit 26.6   |
   | ------------------------------------- | --------------------------- | ------------- | ------------- |
   | вход анимируется (transitionrun/…end) | да                          | да            | да            |
   | выход анимируется                     | да                          | нет           | нет           |
   | transition при закрытии создаётся     | да (×4)                     | не создаётся  | не создаётся  |
   | через 60 мс после hidePopover         | opacity 0.24, translate 76% | display: none | display: none |

   Причина: свойство `overlay` — только Chromium/Edge (Can I Use, 2026-10-03).
   В Firefox/WebKit панель мгновенно покидает top layer и рендеринг —
   отложенный сброс `display: none` (css-transitions-2) не выполняется,
   exit transition не создаётся вовсе. Решение: CSS остаётся каноническим —
   он уже несёт `overlay` в transition-списке (имя парсится как
   `<custom-ident>`, вне Chromium объявление безвредно — вход анимируется
   везде); при появлении `overlay` в FF/WebKit выход начнёт анимироваться
   без изменения CSS. Сегодня выход — graceful degradation: анимирован в
   Chromium, мгновенный в FF/WebKit. Браузерный тест выхода скоуплен
   `CSS.supports('overlay', 'auto')`. Выравнивание выполнено 2026-10-03:
   Dialog/Popover/Tooltip переведены на тот же паттерн (transition на
   элементе, hidden-state в базовых стилях) — с той же деградацией.

6. Новых токенов и APCA-пар нет: `text/surface-raised` (body) — существующая
   запись реестра.

### Squircle-углы: `corner-shape` (2026-10-24)

Аудит (Can I Use MCP, `caniuse_feature` + `browserslist_compatibility_check`
против `.browserslistrc`): `corner-shape` (`wf-corner-shape`) —
Chrome/Edge 139+, Android Chrome 139+; Firefox и Safari — нет (в preview-сборках
за флагом). **progressive enhancement** (Chromium-only).

Решение:

1. `tokens/radius.css`: `@supports (corner-shape: squircle)` — переопределение
   `--ui-radius-xs/sm/md/lg` **удвоением** базовых значений: squircle
   (superellipse(4)) срезает ~0.073·r² площади угла против ~0.215·r² у round,
   совпадение визуального среза требует ≈×1.7 радиуса, ×2 — с запасом
   (проба 2026-10-26: прежние ×1.25–1.5 компенсацию не давали). Риск:
   на элементах ниже 2·radius радиус сжимается браузером — при стилевом
   сомнении задавать `corner-shape: round` локально. Само свойство задаётся
   универсальным селектором (`*`, `::before/::after`, специфичность 0):
   **не наследуется** (css-borders-4; проба 2026-10-26: `:root`-вариант не
   покрывал компоненты), без `border-radius` инертно.
2. Компоненты с `--ui-radius-full` (switch: трек и `::before`, badge) задают
   `corner-shape: round` — при полном сжатии радиуса «углы» занимают
   пол-стороны и squircle превращает стадион в скруглённый прямоугольник
   (проба 2026-10-26).
3. Вне поддержки блок `@supports` пропускается целиком — обычные радиусы.
4. Визуальная калибровка значений — по демо-страницам; изменения значений
   не требуют новых APCA-решений.

### `text-wrap: pretty` — base typography (2026-10-24)

Аудит (Can I Use MCP, `caniuse_feature` + `browserslist_compatibility_check`
против `.browserslistrc`): `text-wrap: pretty` (`wf-text-wrap-pretty`) —
Chrome/Edge 117+, Safari/iOS 26+; Firefox — нет. **progressive enhancement**.

Решение:

1. `base/typography.css`: `p { text-wrap: pretty; }` — балансировка последних
   строк абзацев (устранение «висячих» коротких слов); расширение 2026-10-25:

2. `@supports`-гейт не нужен: движки без поддержки значение игнорируют,
   остаётся обычный UA-перенос. Улучшение чисто типографическое.
3. Не применяется к заголовкам (там каноничен `balance`-поведение, но решение
   по заголовкам не принималось — не расширяем без пробы).

## Процедура обновления

1. Новая platform feature → `caniuse_feature` с точным feature key.
2. При неоднозначности имени — уточнить ключ по результатам поиска (инструмент
   возвращает много похожих совпадений).
3. `browserslist_compatibility_check` против текущего `.browserslistrc`.
4. Проверить partial support и implementation notes.
5. Зафиксировать решение в этой таблице с датой.
6. Реальное поведение подтвердить browser-тестом (Phase 6).

Если Can I Use MCP недоступен, compatibility-sensitive изменения не утверждаются
по памяти — работа приостанавливается до восстановления доступа.
